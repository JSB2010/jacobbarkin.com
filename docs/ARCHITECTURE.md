# System Architecture

## Overview
The **Jacob Barkin Portfolio** is a high-performance, server-side rendered application built on **Next.js 15** and deployed to the edge using **Cloudflare Workers**. This architecture minimizes latency by serving content close to the user while maintaining dynamic capabilities via serverless functions and D1 storage.

## Technology Stack

### Core Framework
-   **Next.js 15 (App Router)**: Utilizes React Server Components (RSC) to reduce client-side JavaScript bundle size.
-   **OpenNext**: A middleware adapter that transforms the Next.js build output into a format compatible with the Cloudflare Workers runtime. It handles the routing and request/response mapping.
-   **TypeScript**: Ensures type safety across the full stack, including database interactions.

### Frontend & UI
-   **Tailwind CSS 4**: Returns to a utility-first styling approach with a focus on performance. JIT engine generates minimal CSS.
-   **shadcn/ui**: Component library built on Radix UI primitives, ensuring accessibility (ARIA compliance) out of the box.
-   **Aceternity UI**: Provides complex, GPU-accelerated animations (e.g., the Wavy Background) using Framer Motion and Canvas.

### Backend Services
-   **Cloudflare Workers**: The compute layer. It executes the Next.js server logic.
-   **Cloudflare D1**: A serverless SQLite database distributed globally. It handles structured data storage (Contact Form Submissions).
-   **Resend**: A developer-centric email API used to send transactional emails (notifications when a user submits the contact form).
-   **Clerk**: Handles Identity and Access Management (IAM). It secures the `/admin` routes via edge middleware.

## Data & Authentication Flow

### Authentication (Clerk)
Protected routes are secured using `src/middleware.ts`.

1.  **Request**: User accesses `/admin`.
2.  **Middleware**: `clerkMiddleware` intercepts the request.
3.  **Check**:
    -   If valid session cookie exists: Request proceeds to the Worker.
    -   If invalid/missing: Redirects to Clerk hosted sign-in page.
4.  **Route Matcher**: `createRouteMatcher` defines explicit public vs. protected paths. Public paths (e.g., `/`, `/about`) bypass auth checks for performance.

### Contact Form Submission
The contact form (`src/app/api/contact/route.ts`) implements a robustness-first approach:

1.  **Client**: React Hook Form collects data -> Zod validates on client -> POST to `/api/contact`.
2.  **Server Validation**: Zod schema re-validates payload on the server.
3.  **Persistence (D1)**:
    -   Retrieves `DB` binding from Cloudflare context.
    -   Executes `INSERT INTO contact_submissions ...` SQL query.
    -   *Fail-safe*: If DB write fails, it logs the error but attempts to send the email anyway.
4.  **Notification (Resend)**:
    -   Constructs email template.
    -   Calls Resend API to deliver notification to `ADMIN_EMAIL`.
5.  **Response**: Returns JSON `{ success: true }`.

## open-next.config.ts
This file controls how OpenNext adapts the Next.js app.
-   It is set to use the **Cloudflare** preset.
-   It ensures the build output targets the JS runtime environment of Workers.

## Wrangler Configuration (`wrangler.jsonc`)
-   **`main`**: Points to `.open-next/worker.js` (the entry point generated by OpenNext).
-   **`compatibility_flags`**: Enables `nodejs_compat` to allow usage of some Node.js APIs within the Worker environment.
-   **`d1_databases`**: Binds the `DB` variable in the worker environment to the specific D1 Database ID (`3b13bb0f...`).
