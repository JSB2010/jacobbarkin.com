# AGENTS.md

Guidance for coding agents working in this repository.

## Project Overview

This is Jacob Barkin's portfolio site. It is a Next.js App Router application deployed to Cloudflare Workers through OpenNext, with Cloudflare D1 for persistent data, Clerk for admin authentication, and Resend for email delivery.

Key areas:
- `src/app`: App Router pages, layouts, route handlers, metadata, sitemap, and robots.
- `src/components`: React components, including `ui` primitives and feature-specific components.
- `src/lib`: Shared server/client utilities, D1 access, API helpers, analytics, embed logic, spam detection, logging, and integrations.
- `public/embed`: Built embed scripts. Treat these as generated outputs unless you are explicitly working on embed distribution.
- `scripts`: Build, migration, image, health, accessibility, and integration helper scripts.
- `migrations` and `src/lib/db/schema.sql`: D1 schema and migration files.
- `worker`: Worker-specific entry/support code.
- `docs`: Architecture, deployment, feature, performance, and security documentation.

## Package Manager and Runtime

- Prefer `bun` for repository scripts because `package.json` scripts already call `bun` in several places and the lockfile is `bun.lock`.
- Do not introduce another package manager lockfile.
- Next.js dev scripts use a local D1 snapshot by default. Use `bun run dev:no-pull` when you do not need to refresh local D1 data.

## Common Commands

- `bun install`: install dependencies.
- `bun run dev`: pull remote D1 snapshot, build embed assets, generate embed instructions, and start Next dev with Turbopack.
- `bun run dev:no-pull`: start local dev without refreshing D1 from remote.
- `bun run build`: build embed assets, generate embed instructions, and run the Next build.
- `bun run build:worker`: build for Cloudflare Workers via OpenNext.
- `bun run preview`: build and preview the Worker locally.
- `bun run lint`: run ESLint for `src`.
- `bun run typecheck`: generate Next types and run TypeScript checks.
- `bun run test:health`: verify `/api/healthz`.
- `bun run test:embed`: build and test embed credit script behavior.
- `bun run check-a11y`: run an axe check against `http://localhost:3000`.

Run the narrowest validation that covers your change. For shared UI, routing, build config, D1, or Worker changes, prefer at least `bun run lint` and `bun run typecheck`; use `bun run build` or `bun run build:worker` when runtime/build behavior may be affected.

## Coding Conventions

- Use TypeScript for app code.
- Follow existing App Router patterns and keep server-only logic in route handlers or `src/lib` modules that are not imported by client components.
- Keep React client components explicit with `"use client"` only when hooks, browser APIs, or client-side interactivity require it.
- Use existing UI primitives and helpers before adding new abstractions. `src/lib/utils.ts` provides the class name merge helper.
- Keep styles aligned with the existing Tailwind/shadcn approach.
- Prefer structured validation with existing Zod schemas and API helpers for route handlers.
- Do not hide lint/type errors with `any`, `@ts-ignore`, or disabled rules unless the local code already requires it and the reason is documented.

## Cloudflare, D1, and Secrets

- Production secrets are managed through Cloudflare/Clerk/Resend and must not be committed.
- Keep `.env.local`, Wrangler state, D1 snapshots, build outputs, and generated caches out of source control.
- Be cautious with remote D1 commands. `bun run d1:migrate` applies migrations remotely; use `bun run d1:migrate:local` for local verification first.
- When changing D1 schema, update both the relevant migration and `src/lib/db/schema.sql` when the local bootstrap schema must reflect the change.
- Worker-targeted code must remain compatible with Cloudflare Workers and OpenNext. Avoid Node-only APIs in code that runs at the edge unless the existing Worker compatibility setup explicitly supports them.

## Generated Files and Assets

- `public/embed/credit.js` and `public/embed/credit.v3.js` are generated by `bun run build:embed`.
- `src/app/embed/instructions.ts` is generated by `bun scripts/generate-embed-instructions.mjs`.
- Do not manually edit generated files unless the task is specifically about the generated artifact and you also update the source script.
- Optimize image assets with the existing image scripts instead of ad hoc tooling.

## Testing Notes

- There is no single universal test runner configured for all code. Use the script that matches the affected area.
- For API and integration changes, inspect existing scripts under `scripts/test-*.js` before adding new testing patterns.
- For frontend behavior, verify responsive states when practical, especially for public pages and forms.
- For accessibility-sensitive UI changes, run `bun run check-a11y` with the dev server running.

## Git and Review Hygiene

- The worktree may contain user changes. Do not revert unrelated edits.
- Before editing generated files or large public assets, confirm whether they are source files or build outputs.
- Keep changes scoped to the request. Avoid broad refactors while making targeted fixes.
- Update documentation in `docs` or root guides when behavior, commands, environment variables, or deployment steps change.
